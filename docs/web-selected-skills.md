# Explicit skills in Web chat

The composer accepts up to three built-in skills through `@` or the Skills entry in the plus menu. Selections apply only to the next message, are removable, and are cleared on send, conversation navigation or account changes. Ordinary access-token refresh in the same login preserves the draft and catalog; user identity, login-session ID and explicit auth invalidation still fence late responses. No skill body is stored in browser storage or conversation history.

Rejected sends, prompt-identity failures and empty/error responses restore the selected draft for retry only when the same login, conversation, navigation and untouched composer still own it. Restoration includes text, uploaded attachment metadata (never revoked thumbnail URLs) and the quote; input edits, newer skill/attachment/quote choices, pending uploads, resets and context changes prevent old work from overwriting a newer draft. Only the exact unsaved optimistic user-message object is rolled back. Reconciled or server-persisted rows are never removed; this is not a server-side exactly-once delivery guarantee after a lost response. Automatic creation of a new conversation uses an explicit guarded draft handoff, not an exception for arbitrary session changes.

`GET /api/skills` requires a signed-in account and returns a bounded bilingual metadata catalog, not skill bodies. `selected_skill_names` accepts only exact names from that catalog. The server verifies the existing trusted-file hashes and attaches guidance to a clone of the current provider-bound user message; the stable system prefix, client-submitted messages and persistence input are unchanged. Office selections include the existing sandbox guide as a dependency. Duplicate reads acknowledge that the guide is already in the current context instead of copying it again.

Selections do not grant tools or permissions, alter model quotas, bypass file ownership checks or authorize computer access. Research, interjections, custom API, native-client and local/remote-computer combinations are not supported by this protocol and are rejected explicitly. File skills require an enabled sandbox and a saved conversation. Search guidance requires Web Search. Existing automatic skill loading remains available without a manual selection.

The noninteractive feedback toast no longer intercepts composer clicks, including after fading out. The picker does not move the composer when it opens, and uses the existing tonal surfaces rather than introducing decorative borders.

Run `node scripts/web-selected-skills-regression.js` for policy, authenticated HTTP/SQLite/mock-provider and desktop/mobile browser regression coverage, including rejected-send retries, attachment/quote recovery, stale-response fencing and same-login token rotation. `--unit-only`, `--runtime-only` and `--browser-only` select narrower checks. Set `RAI_BROWSER_ENGINE=webkit` for WebKit layout and interaction coverage. These tests do not claim physical-device acceptance or real-provider quality.
