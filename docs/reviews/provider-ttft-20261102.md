# 第三方 API 无思考首字延时实测

日期：2026-11-02（Asia/Shanghai）。从当前 RAI 正式服务器发起，只使用合成测试问题，不发送真实用户历史或记忆。新 key 仅保存在服务端权限受限文件中，代码及本报告不包含 key。

## 测量方法

- 比较 `fast.000339.xyz/v1` 与 `xcmapi.org/v1` 的同名 `deepseek-v4.1-flash`。
- `stream=true`、`max_tokens=64`，每个场景每站 5 次，交替请求顺序。
- 首字定义为发起请求至首个非空 `delta.content`，包含连接时间；忽略 HTTP 头、SSE 保活和 `reasoning_content`。
- 新站使用 `thinking:{type:"disabled"}`。旧站仅此参数仍会返回思考内容，因此最终无思考基线额外使用旧站生效的 `reasoning_effort:"none"`。表中 20 个 DeepSeek 样本均未返回思考内容。
- 短系统提示为“你是一个简洁的中文助手。”，用户问题为“请用一句话说明怎样安排今天的工作。”；RAI 场景使用正式版静态主系统提示词（1480 字符）。不包含历史、记忆、附件、搜索、产品请求预处理或客户端渲染。

## 结果

| 场景 | 旧站首字中位数 | 新站首字中位数 | 新站快多少秒 | 样本数 |
|---|---:|---:|---:|---:|
| 短提示词 | 2.5417 秒 | 2.2605 秒 | +0.2812 秒 | 各 5 次 |
| RAI 主系统提示词 | 2.4291 秒 | 2.5353 秒 | -0.1062 秒 | 各 5 次 |

负数表示新站更慢。样本量有限，差异约为零点几秒；本次不能得出“换站会提升数秒”的结论。

## GPT-6.1 Sol

该第三方站点对 `none` 的实际错误为：

```text
gpt-6.1-sol does not support reasoning effort "none"; use low, medium, high, xhigh or max
```

所以产品当前“关闭思考”映射到 `low`，不能把它标注为真正无推理的测量。有效中文短提示词下 3 次 `low` 的首字为 **8.4385、2.7625、2.7496 秒**；中位数 2.7625 秒，范围 2.7496–8.4385 秒。小样本有波动，不代表长历史或高峰负载。

## 额外流式形态探测

同一中文 500 字写作请求、输出上限 1024，Sol 为 `low`，DeepSeek 关闭思考；每项只测 1 次：

| 通道 | 首字 | 最后一个回答文字 | 内容事件数 |
|---|---:|---:|---:|
| Sol Chat Completions | 3.0110 秒 | 18.6789 秒 | 388 |
| Sol Responses | 4.3170 秒 | 23.9797 秒 | 405 |
| 新站 DeepSeek Chat Completions | 2.8201 秒 | 7.1019 秒 | 332 |

本次 Sol Chat 确实逐步流式输出，没有整篇生成后才发首字。改用 Responses 在这次探测中没有改善首字，而且最后文字之后迟迟才结束（总时长 114.0644 秒），因此不建议仅为延时直接切换接口路径。

## 有效方案及其实际边界

1. **先保证无思考参数在供应站生效。** 旧站 DeepSeek 需要 `none`；新站 `thinking:disabled` 已测到不返回思考内容。Sol 此通道最低只能 `low`，不能强制使用 `none`。
2. **日常快答明确选 DS Flash，复杂任务再选 Sol。** 保留用户显式选择的模型。本次 500 字任务中 DS 输出更快，这是模型质量与时延的取舍，不能当作 Sol 本身加速。
3. **保留同一 Sol 模型时，另测独立可用通道。** 用真实长度的脱敏上下文对比后选路，或评估同模型线路超时切换、延迟竞速；后者可能增加调用成本。新提供的 key 在模型列表中只开放 DeepSeek，不能据此评估另一条 Sol 通道。
4. **把产品等待拆成三段计时：发送到上游、上游首字、转发到屏幕。** 源码中的搜索、搜索图片校验、超长上下文压缩、技能读取及工具继续回答可能增加串行等待。本次只测上游，尚未测出产品这些步骤各能节省多少秒，不能靠改提示词承诺数秒提升。
5. **批量工具减少重复往返，技能按需加载。** 本次记忆支持一批最多 500 条，详细规则放在 `memory` skill；普通问答不需要每轮读技能。稳定主提示词及历史前缀继续保留；实际缓存命中与收益需要供应站响应数据证明。
