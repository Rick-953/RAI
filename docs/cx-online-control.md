# Web / CX RAI 在线电脑联动

## 连接与授权边界

- 电脑端显式启用后，电脑向服务端主动注册，不扫描局域网、不开放入站控制端口。
- 同一账号的 Web 只能请求连接自己的在线设备、自己的已保存对话。电脑端核对安全码并批准，批准后连接有效 15 分钟。
- helper 只发送认证心跳并提示/唤醒 UWP；**不得领取、批准、开始或执行工具任务**。UWP 是交互审批和工具执行端。
- 每次操作都需电脑本机确认。连接并非无人值守授权；睡眠、系统注销、未启动 helper、网络断开都不保证可执行。
- 对原生客户端已有的对话，电脑依据服务端验证的 `conversationId` 解析本地已绑定目录；不存在才使用启用远控时选择的目录。最终目录在本机审批中展示并固定，Web 不传入执行根目录。
- `sandbox_exec` 等命令可能影响操作系统，不是安全沙箱承诺；本机确认仍必须展示完整参数，拒绝为默认选项。
- 断开、关闭本机开关、账号/服务源变化、设备租约到期、服务重启都必须停止继续派发。已开始的外部进程是否能取消须由客户端执行器保障，不承诺回滚已发生的修改。

## Web 状态

顶部展示状态点和设备名称，颜色之外还提供文字：

- 绿：本对话连接已批准，最近验证有效。
- 黄：连接中、等待本机授权或重新验证。
- 红：失联、撤销、过期或验证失败。

切换对话不会把电脑授权带到另一个对话，也不会误撤销其他对话。当前标签页的选择仅保存账号 ID、对话/设备/会话 ID 和名称，不保存令牌、设备密钥或文件内容。刷新后必须重新向服务器验证。已选择远程而未连通时，发送失败并显示原因；不得退回云端文件执行。用户必须明确断开才能重新使用云端。

## 协议与故障恢复

实现：`lib/cx-remote-control.js`；Web 控制器：`public/cx-remote.js`。

1. `POST /api/cx-remote/devices`：软件客户端身份 + 用户令牌；随机 `installationId` 为 32–128 个字母/数字/下划线/短横线。不可使用硬件序列号。
2. 同账号重复注册同一 installationId 时去重，轮换设备密钥并撤销旧连接。服务端重启后需重新注册/本机批准；不在服务器持久化客户端秘密。
3. `POST /devices/:id/heartbeat`：用户令牌、软件客户端身份和 `X-CX-Device-Key` 缺一不可。每 10 秒一次，租约 45 秒。返回 `requiresAttention`、待审批/待执行数量和活动连接 ID；不改变任务交付状态。
4. helper 在有待处理事项时以受限频率唤醒 UWP。`GET /devices/:id/poll` 由 UWP 使用，同样的认证，领取的任务附带可信 `conversationId`。
5. 连接审批时限 180 秒，给 UWP 冷启动留时间。审批后连接有效 15 分钟；每个工具任务有效 5 分钟。
6. 本机确认后必须先调用 `/tasks/:id/start` 获取一次性执行资格，再发生副作用。重复 start/result 不得重新执行。丢失 start 响应时应失败关闭，不能盲重试副作用。
7. 协议错误不可一律当网络掉线后静默注册；特别是本机/网页明确撤销和账号鉴权失效，客户端应停止并提示重新启用。
8. 任务完成/取消后立即清理服务端参数与结果引用；后台清扫设备/会话租约，不依赖浏览器继续轮询。

## 自动化回归

- `npm run test:cx-remote`：原有 HTTP 授权、账户/设备/对话隔离、一次执行、撤销、租约、大小限制。
- `node scripts/cx-remote-lifecycle-regression.js`：helper 心跳不消费任务、冷启动等待、对话标识、去重/密钥轮换、异步授权查询中的撤销竞争。
- `npm run test:cx-remote-ui`：Chromium 桌面和实际 touch 输入；WebKit 用 `RAI_BROWSER_ENGINE=webkit`。覆盖控制节点保持、纯文本设备名、绿黄红状态、原对话恢复、掉线禁止云端回退、重新验证、账号变更和页面刷新。
- 菜单/研究模式、模型选择、诊断导出位置、流式插话还必须运行各自回归，不用远程测试替代。

这些是隔离 fixture 和浏览器运行时证明，**不等于真实安装或跨设备验收**。

## 实机验收（须记录事实，未完成不得勾选）

- [ ] 安装新版本后，确认 UWP 和 helper 实际运行版本，而不仅仅是包签名/manifest。
- [ ] 场景 A：电脑新建测试目录，在 CX 的云对话创建文件；手机 Web 打开同一对话，核对设备和安全码，批准后修改；验证修改发生在原目录且内容一致。
- [ ] 场景 B1：UWP 后台、helper 在，Web 能发现并请求；本机被唤醒后显示待批准操作。
- [ ] 场景 B2：关闭 UWP、helper 保留，重复上一项；不得绕过本机确认。
- [ ] 两端设备名和状态一致；断网、休眠/恢复、超时、取消均有明确反馈。
- [ ] 账号切换、显式撤销、本机关闭开关后不能再执行；目录变更需要新的本机确认。
- [ ] 手机刷新/后台恢复、切模型、切对话和重复点击不丢状态、不跨对话执行、不重放文件写入。
- [ ] 同一对话在两端并发修改的冲突行为已检查；不声称自动合并文件内容。

## 发布/回滚

Web 走 feature 分支 → PR → 门禁 → 合并 → `/opt/rai/deploy.sh formal`。更新应用/缓存版本，验证服务健康、公开版本与静态文件 hash。客户端用已有 `打包.ps1` 构建、签名和分架构校验；不得只更新 Web 文案就宣称旧客户端具备 helper 支持。

若联合验收失败，保持明确的未验收状态；可单独交付菜单/设置修复，但不宣称远控完整可用。回滚必须走正常版本控制和部署流程，不手改生产目录、不丢弃并发提交。
