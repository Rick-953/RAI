# RAI Web 代码审查，2026-11-19

基线：`Rick-953/RAI` 的 `main`，`5dda981`，版本 `0.13.53`。修复版本：`0.13.54`。以仓库声明的单 Node.js 进程、SQLite、多用户和同域正式版与 Beta 为前提。这是代码审查，不是生产事故报告。

重点追踪了文件库与聊天附件到带凭据的请求、登录切换到异步显示、会话同步到 IndexedDB、Service Worker 安装到断网导航、固定按钮到 SQLite，以及图片请求到点数扣除和失败退款。没有逐文件审查整个仓库，也没有修改原生 CX RAI 客户端。

## 已修复

| 编号 | 触发情况和影响 | 修复 | 验证 |
| --- | --- | --- | --- |
| 1 | 同一浏览器使用根路径和 `/beta/`，两个数据库可能分配相同用户编号。旧版会读到另一环境的会话列表、消息和图片，清缓存也可能影响另一环境。 | 私有缓存按 API 地址和用户编号分开。启用缓存的用户登录后，只清理这个编号在旧格式下的缓存，不猜测来源，也不动服务器记录。 | 同源两个真实浏览器标签页保存相同会话 ID，验证独立读写、清理和旧缓存升级。 |
| 2 | 私有附件的地址解析器原样接受外域绝对地址，而且下游会添加登录凭据；Beta 的生成图也可能解析到根路径。没有证据表明生产凭据已泄露。 | 请求目标限定为当前服务的上传、生成图或已有文件产物路由，并从当前 API 生成最终地址。 | 正式版、Beta 和 Tauri 三套地址配置；覆盖正常附件、生成图、文件产物及不允许的地址。 |
| 3 | 注销时已打开的附件仍可见；操作前启动的文本预览也可能稍后在新登录状态下打开。另有一个窗口：旧的会话同步读完缓存后，可能按旧清单删除当前缓存。 | 登录状态失效时关闭预览、释放预览资源；异步预览和同步清理在使用结果前复核登录状态。 | 浏览器先打开一条预览，再延迟第二条、注销、放行响应；同步测试在读取版本列表期间切换登录代次。 |
| 4 | 打开验证页后断网，首页显示成验证页；升级时少一个静态资源，新 Worker 仍会激活并淘汰旧缓存。 | 只用当前版本安装成功的首页做离线回退；资源未下载完整则安装失败。运行时缓存限定为本部署的公开资源。 | 两种浏览器实际注册 Worker、访问验证页、断网回首页；另测缺失资源时拒绝激活。 |
| 5 | 两个成功回调互相覆盖，会话和图片读过却不更新最近使用时间。WebKit 临时会话还可能拒存图片，导致已下载的图片也不能预览。 | 在一次事务内读取、更新时间或移除失效记录。浏览器拒绝可选图片写入时返回未缓存，已下载图片继续可用。 | 真实 IndexedDB 验证手动打开、后台预热、过期和持久化时间；覆盖 WebKit 临时会话与磁盘配额错误。 |
| 6 | 第一条固定请求未完成时，第二次点击会清掉第一条的占用标记，第三次点击便会再发请求。取消固定时若重绘面板，失败后也可能只恢复已被替换的旧按钮。 | 只有发起请求的调用能释放标记；失败时恢复当前卡片上的按钮。不改变服务端原有的去重约束。 | 拦住首个 POST 后连续操作；拦住 DELETE、切换语言重绘、返回失败，再用同一按钮成功取消。 |
| 7 | 图片上游在响应头里声明超限时，服务端报错但没有关闭响应流，失败请求可能持续占用连接。 | 声明超限和读取中超限都关闭上游流，不增加重试，也不更改价格。 | 两种长度路径的取消回调；另以本地上游、真实 HTTP 和 SQLite 验证一次扣点、失败及取消退款。 |

## 已落实的后续项

8. **一次性产物只提供下载。** 普通上传保留预览；一次性文件即使被标成图片，渲染时也不发请求。浏览器测试验证只有主动点击下载才取一次文件。切换登录后，晚到的产物下载不再保存，旧删除回执不再更新文件库。

9. **接近 250 MiB 时，不再反复读取正文。** `node scripts/web-cache-capacity-benchmark.js` 在 Chromium 中用 120 MiB 消息和 120 MiB 图片，再预热 50 条小会话。本机单次对照：9,636 ms → 93 ms，采样 JS 堆峰值 485 MiB → 42 MiB（不是进程总内存或手机数据）。复用已有 `meta` 存储，容量、最近读取和版本只读小记录；替换、过期和淘汰与正文一起提交。双标签页覆盖并发写入、刚读取的图片保留、先淘汰最旧图片、手动清除和修订列表。
